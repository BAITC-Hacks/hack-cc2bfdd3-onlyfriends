# Архитектура

## Поток одного запуска

```text
origin_at + конфигурация двух турбин
        ↓
агент-оркестратор → архивный выпуск погоды → проверка публикации и полноты
        ↓
подготовка признаков → модель → проверка 48 почасовых значений
        ↓
сохранение результата и происхождения → краткий анализ аномалий
```

Для ретропрогноза управляющий сценарий проходит даты последовательно. На каждом шаге доступность данных определяется моментом запуска, а не текущим временем машины.

## Текущая реализация

| Модуль | Ответственность |
| --- | --- |
| `windpower/weather.py` | Архивный выпуск Open-Meteo для фиксированных координат и локальный кеш |
| `windpower/source_search.py` | Ограниченный поиск текущих веб-страниц для исследования источников |
| `windpower/agent_tools.py` | Тонкие адаптеры инструментов LangChain |
| `windpower/features.py` | Подготовка признаков из проверенного погодного выпуска |
| `windpower/forecast.py` | Проверка времени, полноты и диапазона прогноза; сводка результата |
| `windpower/agent.py` | Граф одного запуска и последовательный прогон по дням |
| `windpower/store.py` | Версионный JSON-результат с происхождением данных |

Поисковый инструмент доступен отдельно от прогнозного графа. Современная интернет-выдача не добавляется к признакам при восстановлении прогноза за февраль 2026 года.

## Предлагаемые границы в `src/`

| Компонент | Ответственность |
| --- | --- |
| `domain/forecast/` | Временные и числовые инварианты, доменные типы |
| `application/` | Сценарии импорта, обучения и одного расчёта |
| `agents/` | Конечный цикл оркестрации и выбор разрешённого следующего действия |
| `infrastructure/weather/` | Получение и разбор архива погодных выпусков |
| `infrastructure/storage/` | Запись/чтение версий модели, исходных выпусков и результатов |
| `cli/` | Будущие команды воспроизводимого запуска |

Папки появляются только вместе с кодом. Направление зависимостей: CLI/агент → application → domain; инфраструктура реализует входные контракты приложения.

## Контракты данных

- **Наблюдение ВЭС:** `turbine_id` или идентификатор станции, `observed_at`, скорость ветра, температура, нормализованная активная мощность, флаг качества. Пустые и повторяющиеся часы разбираются явно.
- **Погодный выпуск:** провайдер, модель, запрошенные координаты и координаты ячейки модели, `initialized_at`, `available_at`, `valid_at`, высота измерения ветра, единицы, значения и исходный запрос/ответ или контрольная сумма.
- **Запуск:** `run_id`, `origin_at`, версия модели и набора признаков, параметры, статус, диагностические сообщения.
- **Прогноз:** `run_id`, объект прогноза, `valid_at`, горизонт в часах `1..48`, значение в подтверждённой единице и ссылка на погодный выпуск.

Если исходный файл содержит только показатель станции, система не создаёт фиктивные цели по двум турбинам: координаты используются для погодных признаков, а прогнозируется подтверждённая целевая величина.

## Инварианты и отказы

Перед расчётом проверяются уникальность часов, ожидаемая длина горизонта, разумность значений и `available_at <= origin_at`. Сведения, опубликованные позднее, отклоняются до построения признаков. Отсутствующий выпуск, неполный горизонт и несовместимая модель дают статус ошибки с причиной. Повтор запуска с тем же ключом возвращает существующий результат или создаёт явную новую версию; молчаливой перезаписи нет.
