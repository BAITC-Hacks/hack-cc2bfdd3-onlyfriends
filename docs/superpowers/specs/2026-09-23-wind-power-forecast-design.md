# Прогноз выработки ВЭС: design spec

## Цель и границы

Система обучает модель нормализованной почасовой активной мощности и выпускает 48 почасовых прогнозов для каждой даты выпуска. При ретропрогнозе с 31 января по 28 февраля 2026 года она использует только метеопрогноз, уже доступный на момент выпуска. Метрики февраля считаются только при наличии фактической мощности; эти значения никогда не участвуют в подборе модели.

Координаты: турбина 1 — 43.645150, 78.535604; турбина 2 — 43.643198, 78.538828. Время исходных измерений считаем локальным `Asia/Almaty`, если пользователь не укажет другое. Выпуск — ежедневно в 00:00 локального времени; горизонты 1–24 и 25–48 часов оцениваются отдельно. Временные метки, события и выбор запуска модели погоды хранятся в UTC.

## Входные данные

В `raw/` лежат два CSV, по одному на турбину. Каждый содержит время, скорость ветра в м/с, температуру в °C и нормализованную мощность с шагом 10 минут. В обоих файлах измерения заканчиваются 2026-01-31 23:50, февральских меток нет. Точные русские названия колонок фиксируются в загрузчике, номер турбины берётся из имени файла. Один час получается средним из как минимум четырёх корректных 10-минутных измерений; часы с меньшим покрытием исключаются из обучения и метрик. Дубли времени, неоднозначные временные метки и нечисловые значения учитываются явно. Целевые значения вне `[0, 1]` исключаются с отчётом о количестве. Данные после 2026-01-31 23:59 по местному времени исключаются из обучения и подбора.

## Архив погоды без утечки

Источник — Open-Meteo Single Runs API, фиксированная модель ECMWF IFS HRES, доступная для дат кейса с марта 2024 года. В запросе задаются координаты, UTC, скорость ветра на 10 и 100 м, направление на 100 м, температура на 2 м и давление; скорость запрашивается в м/с. Для ежедневного выпуска в 00:00 `Asia/Almaty` выбирается последний цикл UTC 00/06/12/18, завершившийся не позднее чем за 7 часов до выпуска. Для данного расписания это обычно цикл 12 UTC предыдущего дня. Файл каждого ответа кэшируется с метаданными `run`, `issue_time`, URL/параметры и SHA-256. При ошибке или неполных 48 часах выпуск не подменяется фактической погодой: журнал получает ошибку, повтор запуска возможен после восстановления источника.

Измеренный ветер — только дополнительная метка для двухэтапной модели и диагностики; при прогнозировании он недоступен. Для обучения прямой модели признаки берутся из архивных прогнозов на конкретный горизонт. Так обучение и прогноз используют один тип входных данных.

## Модели и контроль переобучения

Сравниваются: (1) простая эмпирическая кривая мощности по прогнозному ветру; (2) прямая CatBoost-модель по архивному прогнозу погоды, горизонту и календарным признакам; (3) двухэтапный вариант — коррекция прогнозного ветра по измеренному ветру на обучающем отрезке и модель мощности по измеренному ветру. Двухэтапный вариант запускается только если есть качественные измерения ветра. Признаки календаря циклические; признаки, недоступные при выпуске, запрещены. Предсказания ограничиваются `[0, 1]`.

Модели сравниваются на помесячных скользящих срезах до февраля 2026 года: для каждого месяца обучение использует только предшествующие ему наблюдения и архивные прогнозы. Основная метрика — MAE нормализованной мощности, дополнительные — RMSE, bias, MAE для горизонтов 1–24 и 25–48. Подбор ограничен небольшой заранее заданной сеткой глубины и регуляризации; победитель должен улучшать базовую модель на нескольких месяцах, а не только на одном. Февраль не используется для обучения, ранней остановки, выбора модели или подбора коэффициентов. После выбора финальная модель переобучается на всех допустимых данных до отсечки.

## Исполнение и результат

CLI выполняет последовательность `fetch-weather`, `train`, `forecast`, `backtest`. Команда `run` проверяет кэш и данные, обновляет доступный прогноз погоды, при необходимости переобучает модель, выпускает прогноз и записывает диагностический отчёт. Результат содержит `issue_time_utc`, `run_time_utc`, `valid_time_utc`, локальное время, турбину/станцию, горизонт, прогноз мощности и версию модели. Повторный запуск с теми же входами идемпотентен; новый погодный запуск создаёт новую версию прогноза, не затирая старую.

Артефакты: сериализованная модель с метаданными, таблица метрик по месяцам и горизонтам, CSV прогнозов по каждой турбине, JSON журнала агентского цикла. Дополнительно выводится сумма двух нормализованных мощностей с единицей «эквивалент номинала одной турбины»; МВт·ч без паспортной мощности не заявляются. README описывает установку, схему данных, команды и ограничения данных.

## Проверки

Автотесты проверяют выбор погодного запуска, 48 часов без пропусков, отсечку тренировочных дат, отсутствие февральской цели в подборе, временной порядок folds, границы мощности и повторяемость вывода. Интеграционный тест использует синтетическую историю только для проверки исполнения; её метрики не выдаются за качество на ВЭС.

## Риски и решения

- Разница между ветром на турбине и ветром в сетке ECMWF: прямое обучение на прогнозах и отдельный кандидат коррекции ветра.
- Остановы и ограничения мощности: обе модели обучаются на реальной целевой мощности; отчёт отдельно показывает долю нулевой мощности при сильном ветре.
- Неизвестная часовая зона исходного файла: задаётся явно, по умолчанию `Asia/Almaty`; после получения файла сверяется с его описанием.
- Архивы для точных циклов могут отсутствовать: ошибка видна в журнале, никакой подмены погодой из будущего.

Источник архива: https://open-meteo.com/en/docs/single-runs-api
