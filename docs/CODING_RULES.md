# Правила реализации

Обязательный полный набор правил находится в корневом [AGENTS.md](../AGENTS.md). Этот файл связывает их с кейсом ВЭС.

## Ответственность

- Один модуль решает одну задачу: загрузка истории, погодный адаптер, подготовка признаков, модель, проверка результата, оркестрация.
- Агент управляет последовательностью действий; вычисление признаков, прогноз и проверки реализуются обычным кодом.
- Внешний API и файловый ввод находятся на границе системы. Доменный код не зависит от конкретного погодного провайдера.
- Ввод, вывод и ошибки каждого публичного действия имеют явную схему. Ошибки источника, валидации и недоступного выпуска различаются.

## Работа со временем

- Все внутренние метки хранятся как timezone-aware UTC. Исходный часовой пояс фиксируется при импорте.
- Для каждого значения различаются `initialized_at` (инициализация погодной модели), `available_at` (публикация результата), `valid_at` (час прогноза) и `origin_at` (момент запуска).
- Любой признак подтверждает `available_at <= origin_at`. При неизвестном времени доступности источник нельзя объявлять честным для ретропрогноза.
- Деление на обучение и проверку делается по времени, без случайного смешивания часов или запусков.

## Качество кода

- Изменения минимальны для текущей задачи; новые зависимости добавляются только при необходимости.
- Побочные эффекты повторяемы: ключ результата включает момент запуска, турбину/станцию и версию расчёта.
- Сетевые запросы имеют тайм-аут, ограниченное число повторов и явный отказ. Нельзя бесконечно повторять вызовы агента.
- Для критических правил есть тесты: временная доступность, 48 часов, пропуски, единицы, идемпотентность и внешние сбои.
- После реализации выполняются имеющиеся тесты, проверка типов и форматирование; README содержит реально проверенные команды.

Правило по размеру исходных файлов, комментарии к публичным функциям и остальные требования берутся напрямую из [AGENTS.md](../AGENTS.md).
