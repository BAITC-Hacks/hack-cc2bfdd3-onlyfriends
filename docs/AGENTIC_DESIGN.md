# Дизайн агента

## Роль

Один агент отвечает за ежедневный цикл прогноза: получить допустимые входные данные, вызвать расчёт, проверить выход, сохранить результат и решить, нужен ли ограниченный повторный запрос при обновлении данных. Отдельные агенты пока не нужны: границы ответственности между ними в первой версии отсутствуют.

Агент не обучает модель «рассуждением» и не вычисляет мощность текстом. Числовые правила и допуск к данным проверяет код. Модель прогнозирования и погодный адаптер предоставляются как отдельные прикладные действия.

## Разрешённые действия

| Действие | Результат |
| --- | --- |
| `fetch_weather_run` | Один архивный выпуск для координат и времени |
| `search_web` | Ссылки и короткие фрагменты для исследования источников вне ретропрогноза |
| `save_weather_run` | Неизменяемая копия исходного ответа и метаданных |
| `validate_inputs` | Структурированный отчёт о доступности и полноте |
| `build_features` | Признаки только из допустимых данных |
| `predict_power` | 48 почасовых оценок и версия модели |
| `validate_forecast` | Проверка часов, диапазона и аномалий |
| `analyze_forecast` | Сводка нормализованной мощности за оба 24-часовых окна |
| `assess_operations` | Детерминированные 3-часовые изменения и периоды низкой средней нормализованной мощности двух турбин |
| `save_forecast` | Идемпотентно сохранённый прогноз с происхождением |

Текущий исполняемый граф реализован в `windpower/agent.py`. Его узлы: `validate_request` → `fetch_weather_run` → `validate_inputs` → `build_features` → `predict_power` → `validate_forecast` → `analyze_forecast` → `assess_operations` → `save_forecast`. После ошибки переход идёт в конец графа с кодом отказа; успешный запуск даёт 96 строк, по 48 часов для каждой турбины, и сводку мощности для двух 24-часовых окон. Получение погоды и исследовательский поиск оформлены как инструменты LangChain, предиктор вызывается через LangChain Runnable, маршрутизация выполняется LangGraph. `search_web` доступен через `research_sources`, но не включён в прогнозный граф: сегодняшняя интернет-выдача не может служить погодой прошлого. `save_weather_run` реализован как кеширование исходного ответа внутри погодного адаптера. Прогноз обученной модели передаётся в агент через функцию-предиктор; артефакт модели выбирается по времени выпуска и сохраняется с версией. Конкретные входы, выходы и ограничения описаны в [TOOLS](TOOLS.md).

## Цикл и остановка

1. Получить `origin_at`, обе координаты и зафиксированную конфигурацию.
2. Найти последний архивный погодный выпуск, доступный не позже `origin_at`; сохранить точный выпуск и основание оценки доступности.
3. Проверить данные. При временной внешней ошибке повторить запрос ограниченное число раз; если выпуск отсутствует или он поздний — завершить с явным отказом.
4. Построить признаки, получить прогноз и проверить 48 уникальных последовательных часов.
5. Сохранить результат и краткий отчёт. При новом выпуске запустить новый расчёт с новой версией входа, не переписывая историю.

`run_daily` повторяет этот граф для последовательных UTC-дней с пределом 29 запусков и останавливается при первом отказе. Это позволяет явно увидеть неполный ретропрогноз и затем продолжить работу после устранения причины.

Остановка: один успешный сохранённый прогноз либо классифицированная ошибка после лимита попыток. Передача человеку нужна при неподтверждённой схеме данных, недоступном архиве или устойчивой аномалии, которую нельзя исправить разрешёнными действиями.

## Применение LLM

LLM отвечает на вопросы по выбранному сохранённому прогнозу и может кратко интерпретировать диагностические сигналы. Пик мощности и изменение между выпусками вычисляются кодом без арифметики LLM. Текстовый ответ проверяется на непустоту, но не является доказанной причиной погоды или оперативным распоряжением. Он не меняет численный прогноз, временные ограничения или журнал шагов агента.

Локальный JSON содержит `run_id`, версию модели, время погодного выпуска, хеши входа и результата, сводку прогноза и статусы шагов. Исходный погодный ответ хранится в отдельном кеше. При `LANGSMITH_TRACING=true` и наличии `LANGSMITH_API_KEY` LangSmith получает дерево выполнения LangGraph; входы, выходы и метаданные скрыты клиентом, чтобы не отправлять таблицы и секреты. Без ключа граф работает локально. Время публикации архивного выпуска пока оценивается правилом `run_time_utc + 7h` и требует подтверждения для строгой исторической оценки.

## Операционная сводка и повторный расчёт

Узел `assess_operations` после проверки прогноза вычисляет среднюю нормализованную мощность двух турбин и сохраняет в том же неизменяемом JSON окна изменения на 25 процентных пунктов за 3 часа, а также периоды не выше 15% продолжительностью не менее 3 часов. Пороги — правила привлечения внимания, не физические пределы ВЭС и не оценка потребности в резерве в МВт. Вопрос об изменении прогноза агент отвечает по числам сохранённых выпусков без арифметики LLM.

В режиме live открытый сайт каждые 15 минут запрашивает новый погодный вход и запускает полный граф. API сравнивает только общие прогнозные часы с предыдущим сохранённым запуском. При ретропрогнозе предшественником может быть только более ранний выпуск, поэтому показанный пересчёт не использует будущие прогнозы. История хранится по разным `run_id`. Для работы при закрытом браузере `python -m windpower.watch` периодически проверяет live-погоду: при неизменных погодных значениях и версии модели для того же часа выпуска он повторно использует прежний результат, а при изменении запускает граф с уже полученным погодным снимком. Процесс наблюдения необходимо держать запущенным.
