# Дизайн агента

## Роль

Один агент отвечает за ежедневный цикл прогноза: получить допустимые входные данные, вызвать расчёт, проверить выход, сохранить результат и решить, нужен ли ограниченный повторный запрос при обновлении данных. Отдельные агенты пока не нужны: границы ответственности между ними в первой версии отсутствуют.

Агент не обучает модель «рассуждением» и не вычисляет мощность текстом. Числовые правила и допуск к данным проверяет код. Модель прогнозирования и погодный адаптер предоставляются как отдельные прикладные действия.

## Разрешённые действия

| Действие | Результат |
| --- | --- |
| `fetch_weather_run` | Один архивный выпуск для координат и времени |
| `search_web` | Ссылки и короткие фрагменты для исследования источников вне ретропрогноза |
| `save_weather_run` | Неизменяемая копия исходного ответа и метаданных |
| `validate_inputs` | Структурированный отчёт о доступности и полноте |
| `build_features` | Признаки только из допустимых данных |
| `predict_power` | 48 почасовых оценок и версия модели |
| `validate_forecast` | Проверка часов, диапазона и аномалий |
| `analyze_forecast` | Сводка нормализованной мощности за оба 24-часовых окна |
| `save_forecast` | Идемпотентно сохранённый прогноз с происхождением |

Текущий исполняемый граф реализован в `windpower/agent.py`. Его узлы: `validate_request` → `fetch_weather_run` → `validate_inputs` → `build_features` → `predict_power` → `validate_forecast` → `analyze_forecast` → `save_forecast`. После ошибки переход идёт в конец графа с кодом отказа; успешный запуск даёт 96 строк, по 48 часов для каждой турбины, и сводку мощности для двух 24-часовых окон. Получение погоды и исследовательский поиск оформлены как инструменты LangChain, предиктор вызывается через LangChain Runnable, маршрутизация выполняется LangGraph. `search_web` доступен через `research_sources`, но не включён в прогнозный граф: сегодняшняя интернет-выдача не может служить погодой прошлого. `save_weather_run` реализован как кеширование исходного ответа внутри погодного адаптера. Прогноз модели передаётся в агент через функцию, поскольку обученной модели пока нет. Конкретные входы, выходы и ограничения описаны в [TOOLS](TOOLS.md).

## Цикл и остановка

1. Получить `origin_at`, обе координаты и зафиксированную конфигурацию.
2. Найти последний архивный погодный выпуск, доступный не позже `origin_at`; сохранить точный выпуск и основание оценки доступности.
3. Проверить данные. При временной внешней ошибке повторить запрос ограниченное число раз; если выпуск отсутствует или он поздний — завершить с явным отказом.
4. Построить признаки, получить прогноз и проверить 48 уникальных последовательных часов.
5. Сохранить результат и краткий отчёт. При новом выпуске запустить новый расчёт с новой версией входа, не переписывая историю.

`run_daily` повторяет этот граф для последовательных UTC-дней с пределом 29 запусков и останавливается при первом отказе. Это позволяет явно увидеть неполный ретропрогноз и затем продолжить работу после устранения причины.

Остановка: один успешный сохранённый прогноз либо классифицированная ошибка после лимита попыток. Передача человеку нужна при неподтверждённой схеме данных, недоступном архиве или устойчивой аномалии, которую нельзя исправить разрешёнными действиями.

## Применение LLM

LLM может интерпретировать диагностические сигналы и предложить действие из ограниченного набора. Его вывод валидируется по схеме; он не изменяет временные ограничения, не выбирает произвольный URL, не подменяет отсутствующие данные и не принимает текстовый прогноз за расчёт модели. Если такая интерпретация не даёт измеримой пользы, цикл остаётся детерминированным с тем же журналом действий.

Локальный JSON содержит `run_id`, версию модели, время погодного выпуска, хеши входа и результата, сводку прогноза и статусы шагов. Исходный погодный ответ хранится в отдельном кеше. При `LANGSMITH_TRACING=true` и наличии `LANGSMITH_API_KEY` LangSmith получает дерево выполнения LangGraph; входы, выходы и метаданные скрыты клиентом, чтобы не отправлять таблицы и секреты. Без ключа граф работает локально. Время публикации архивного выпуска пока оценивается правилом `run_time_utc + 7h` и требует подтверждения для строгой исторической оценки.
