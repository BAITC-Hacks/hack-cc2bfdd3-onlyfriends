# OnlyFriends — прогноз выработки ВЭС

Проект для трека Самрук-Казына: почасовой прогноз выработки ветроэлектростанции на следующие 24–48 часов. Система должна ежедневно получать архивный прогноз погоды, доступный на дату запуска, готовить данные, рассчитывать и проверять прогноз, сохранять результат с происхождением данных.

## Статус

Реализованы загрузка и почасовая подготовка истории ВЭС, адаптер архивного прогноза Open-Meteo, построение признаков и один цикл агента. Агент использует LangGraph для шагов и остановки при ошибке, LangChain для погодного инструмента и вызова предиктора, LangSmith для необязательной трассировки. Обученная модель, воспроизведение всего февраля и метрики качества ещё не реализованы; реальный прогноз невозможен до подключения модели и проверки исходных данных.

## Исходные условия

- История ВЭС: март 2023 — 31 января 2026 включительно.
- Тестовый период: 1–28 февраля 2026.
- Поля из задания: статистическое время, средняя скорость ветра (м/с), нормализованная активная мощность на стороне линии, средняя температура воздуха (°C).
- Турбина 1: `43.645150, 78.535604` ([карта](https://maps.app.goo.gl/iN6svMt69D5qRpFU9)); турбина 2: `43.643198, 78.538828` ([карта](https://maps.app.goo.gl/8UQMwsYavY6nLvFY8)). Координаты извлечены из перенаправлений ссылок организаторов; их следует сверить с исходным файлом.

Каждый ежедневный запуск выдаёт 48 почасовых значений; первые 24 часа образуют отдельный срез. Время запуска и часовой пояс фиксируются после проверки исходных меток. В февральскую оценку входят только целевые часы февраля; прогноз запуска 28 февраля может включать март, но эти часы не входят в февральские метрики.

**Правило ретропрогноза:** для момента запуска `origin_at` разрешены лишь данные, опубликованные и доступные не позже `origin_at`. Погодные наблюдения, реанализ и более поздние прогнозы нельзя подставлять вместо архива доступного тогда прогноза.

## План воспроизведения после реализации

1. Получить файл истории ВЭС и проверить схему, часовой пояс, пропуски и смысл нормализации мощности.
2. Зафиксировать момент ежедневного запуска и погодный источник с архивом отдельных выпусков.
3. Обучить модель только на доступной к моменту обучения истории; сохранить версию модели и признаков.
4. Последовательно пересчитать 31 января и каждый день февраля 2026 года; сохранить 48 значений, погодный выпуск и время его публикации.
5. Сравнить прогнозы с фактическими значениями февраля по [правилам оценки](docs/EVALS.md).

Зависимости описаны в `pyproject.toml` и зафиксированы в `uv.lock`. Для проверки текущего кода:

```powershell
uv sync --group dev
uv run --group dev pytest -q
```

`ForecastAgent` принимает функцию `predictor(features) -> DataFrame`, которая возвращает `turbine_id`, `valid_time_utc`, `lead_hour`, `predicted_power` для 48 часов по каждой турбине. Вызов `ForecastAgent(...).run(issue_utc)` принимает точный час UTC и возвращает `AgentResult`; успешный запуск сохраняет JSON с прогнозом, сводкой мощности по двум 24-часовым окнам, временем и хешем погодного выпуска и версией модели. Исходный ответ погоды хранится отдельно в кеше. До подключения обученной модели этот контракт проверяется синтетическим предиктором в `tests/test_agent.py`; тестовые значения не являются прогнозом ВЭС.

Для трассировки задайте `LANGSMITH_TRACING=true`, `LANGSMITH_API_KEY` и, при желании, `LANGSMITH_PROJECT`. Ключ задаётся только через переменную окружения. Агент отправляет в LangSmith структуру шагов и их статус, скрывая входы, выходы и метаданные трассы; без ключа выполняется локально. Для ретропрогноза потребуется отдельно подтвердить фактическое время публикации погодных выпусков: текущая проверка использует консервативную оценку `run_time_utc + 7h <= issue_time_utc`.

## Что требует подтверждения

- Фактическая схема файла: строки по турбинам или общий показатель станции.
- Часовой пояс и смысл поля «статистическое время».
- Диапазон и база нормализации мощности; есть ли установленная мощность для перевода в МВт·ч.
- Доступность погодного архива для обеих координат, 48 часов и время публикации выпусков.
